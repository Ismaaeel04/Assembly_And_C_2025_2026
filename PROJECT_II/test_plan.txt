Test Plan and Test Cases
========================

Name: Ismael Charaf Megrini
Date: 4/29/2026


1. Overview
-----------

This document describes the tests used to verify the converted x86_64 
assembly code works correctly. The main thing being tested is the 
REGISTER_ADDER function which adds two numbers using register parameter 
passing.

The tests are written in C using the assert macro from the assert.h 
library. If any assert fails the program stops immediately and shows 
which line failed.


2. How to run the tests
-----------------------

In the terminal:

    make test

The Makefile compiles adder.asm with NASM, compiles test_adder.c with 
GCC, links them together and runs the test program.

If everything passes you will see "All tests passed!" at the end. If 
something fails the program stops with an assertion error.


3. Test cases
-------------

Test 1: Simple positive numbers
    Input: 5 + 10
    Expected: 15
    Reason: Basic check that the function adds two normal positive numbers.

Test 2: Adding zero
    Input: 0 + 7
    Expected: 7
    Reason: Make sure adding zero doesn't break anything.

Test 3: Both zero (edge case)
    Input: 0 + 0
    Expected: 0
    Reason: Edge case to confirm the function returns 0 when both inputs 
    are 0.

Test 4: Bigger numbers
    Input: 100 + 250
    Expected: 350
    Reason: Test with larger values to make sure the function works for 
    bigger numbers too.

Test 5: One negative number
    Input: -5 + 10
    Expected: 5
    Reason: Confirm the function handles signed (negative) numbers 
    correctly.

Test 6: Both negative numbers
    Input: -3 + -4
    Expected: -7
    Reason: Edge case for two negative numbers, result should be more 
    negative.

Test 7: Running sum (3 iterations)
    Input: 5 + 10 done 3 times, accumulated
    Expected: 45
    Reason: This matches the logic of the main program which loops 3 
    times and adds each result to a running total.


4. Manual test of the main program
----------------------------------

The main program (sum_program.asm) is also tested by running it with 
known inputs and checking the output is correct.

Run with:

    make

Example test run:

    Enter number: 5
    Enter number: 10
    The sum is: 15
    Enter number: 3
    Enter number: 7
    The sum is: 10
    Enter number: 1
    Enter number: 2
    The sum is: 3
    Final sum is: 28


5. What is not tested
---------------------

- Overflow when numbers are too big. The original 68000 code had a 
  comment about no bounds checking and this port has the same issue. 
  Adding overflow detection would need extra code and was left out to 
  keep the port simple.

- Invalid input from the user (like typing letters instead of numbers). 
  The original code marked this as "Vulnerable!" and this port keeps 
  the same behaviour for the same reason.


6. Results
----------

All 7 automated tests pass. The manual test of the main program also 
produces the expected output. The conversion from 68000 to x86_64 
works correctly.
